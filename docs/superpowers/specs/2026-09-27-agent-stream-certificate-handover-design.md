# Agent 控制流证书交接设计

## 目标

Agent 续签客户端证书后，既有 WebSocket 可在同一连接中切换到新证书做身份复核，避免旧证书到期引发控制流断开并关闭正在服务的转发与代理连接。异常断线、租约到期和吊销继续按现有机制关闭数据面。

## 协议

协议版本仍为 1，新增 `certificate_update` 和 `certificate_update_ack` 消息。Agent 保存新证书后发送 `{certificate_pem}`；控制面要求连接原始 mTLS 证书已验证，解析 PEM 单证书，核对节点 URI、客户端用途、Ed25519 公钥与本连接原始 TLS 证书相同，然后通过在线证书授权查询验证新指纹。成功后，将此连接的周期复核目标切换为新证书，返回 `{fingerprint}` 确认。更新与心跳、配置和额度消息共用现有单写锁。

Agent 在确认前每 10 秒重发同一张证书。服务器重复接收同一证书时重复确认；失去连接后，下一次 TLS 握手从已落盘的新证书加载。Agent 只接受与待确认证书 SHA-256 指纹一致的确认，不因错误确认停止重试。证书正文只用于授权验证，不包含私钥。

## 状态与边界

控制面只更新该 WebSocket 内存中的当前复核证书；数据库授权表不因交接而改变。旧证书的 TLS 握手状态不会被伪装为新证书：同密钥且当前链路已验证，是这次同连接交接的必要条件。服务器每次处理更新时重新查数据库；节点停用、重新入网或授权过期时拒绝并终止流。证书更新消息不得切换节点或密钥。控制流在交接前仍以旧证书复核，因此 Agent 必须在旧证书过期前取得确认。

## 验收

- 严格解析与拒绝未知、重复、过大字段和无效 PEM。
- 拒绝不同节点、不同公钥、未授权、过期或被吊销的新证书。
- 同证书重复更新可确认；Agent 仅认匹配指纹的确认。
- 旧证书过期后，只要新证书已确认，控制流、配置租约和现有 TCP/UDP/Trojan 会话继续有效。
- 断线、租约过期和吊销仍关闭运行时；升级兼容性由新增消息的协商或兼容部署顺序保证。
