# Agent 入网身份设计

本设计细化已确认的控制面与 Agent 架构。公开纯 IP 预览继续只读；入网请求只在独立 TLS 入口开放，不能经当前明文 HTTP 端口提交令牌或证书请求。

## 边界与流程

管理员在已认证的 HTTPS 控制台中提交当前密码重新认证，为一个已存在、已启用的节点创建一次性入网令牌。签发操作在同一事务写入不含明文令牌的审计记录。令牌由 32 字节随机数生成，10 分钟到期，数据库只存 SHA-256；同一节点重新签发时旧未用令牌失效。现有浏览器认证功能须在 HTTPS 可用后才开启；上线前可用受限的本地管理命令调用同一服务。

Agent 在本机生成 Ed25519 私钥并发送 PKCS#10 CSR 与一次性令牌。入网服务先校验令牌、节点状态及 CSR 签名，再以控制面专用 CA 签发 24 小时客户端证书。证书含 `spiffe://network-control-plane/agent/{node_id}` URI，扩展用途仅为客户端认证；服务端覆盖 CSR 中的身份字段。签发、令牌消费和 Agent 证书指纹更新由同一数据库事务完成。失败不消耗令牌；并发重放只允许一个成功。返回证书及 CA 链，私钥始终留在 Agent。

Agent 流入口要求 mTLS，先验证证书链和有效期，再从 URI 提取节点 ID，并与数据库中的证书指纹和未撤销状态比较。消息 envelope 的 `node_id` 必须与证书身份一致。吊销或换证立即使旧证书失效；长期连接须定期复核数据库状态或被主动关闭。

## 数据与安全

新增 `agent_enrollment_tokens`，字段为 `id`、`node_id`、`token_hash`、`created_by`、`created_at`、`expires_at`、`consumed_at`，对 token hash 唯一，按节点与到期时间建立索引。`agents` 增加证书到期时间。CA 私钥只从受限文件加载，不入数据库、不写日志或 API 响应；服务启动时校验 CA 证书与私钥匹配，且证书可签发客户端证书。证书生成使用独立包，数据库事务封装在入网仓储中。令牌与 CSR 请求设大小上限、统一错误和速率限制。生产 TLS 服务端证书必须覆盖所用 IP 或域名，客户端预先安装可信 CA，禁止跳过验证。

## 验收

有效令牌只签发一次；过期、重放、错误节点、损坏 CSR、关闭节点及非 Ed25519 CSR 被拒绝。签发的证书通过 CA 验证，携带正确节点 URI 和客户端认证用途；Agent 私钥不进入控制面。mTLS 流入口拒绝无证书、旧指纹、吊销节点及 envelope 节点冒用。PostgreSQL 16 独立库验证事务与并发；真实 Agent 和控制面在 TLS 上完成入网和配置 ACK 后，才可将转发状态标为已生效。
