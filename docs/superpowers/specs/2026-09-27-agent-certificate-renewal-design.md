# Agent 客户端证书自动续签设计

## 问题

Agent 客户端证书只有 24 小时有效期。现有一次性令牌只适合首次入网；运行中的 Agent 无法在无人值守时取得下一张证书，长期连接会在证书失效后被控制面拒绝。

## 协议

新增专用 TLS 入口 `POST /api/v1/agent/renew`。请求必须带当前受信任且数据库仍授权的 Agent mTLS 证书；正文只包含用该 Agent 现有 Ed25519 私钥签名的 CSR 和 Agent 版本。控制面从 TLS 证书提取节点身份，重新校验数据库指纹、节点启用状态和证书有效期；CSR 公钥必须与当前证书公钥相同。服务端签发另一张 24 小时客户端证书，返回证书、CA 和到期时间；不接收一次性令牌。

证书授权采用同一节点的有限重叠窗口。新增 `agent_certificate_grants` 表，按节点和指纹保存续签证书、公钥证书正文、父证书指纹及到期时间。现有 `agents.cert_fingerprint` 保留首次入网证书；认证接受当前证书或该节点未过期的续签证书。每次续签在节点行锁下写入授权，限制同时有效的续签证书数量；同一父证书重试返回相同证书，避免响应丢失造成重复授权。拒绝过早续签（当前证书剩余有效期超过 6 小时）和过期证书。重新入网时删除该节点所有续签授权；节点停用期间所有证书失效，重新启用后尚未过期的证书恢复可用。`agents.status='revoked'` 会拒绝身份验证，但当前没有单独的永久吊销管理操作。定期清理过期授权。

Agent 在证书剩余 6 小时内发起续签，失败后每 5 分钟重试并在成功前保留旧证书。续签沿用现有私钥，避免证书与私钥两个文件无法原子替换；新证书写入同目录临时文件、`fsync` 后原子改名并同步目录。新的 TLS 握手从证书文件重新加载证书，已建立的 WebSocket 可以使用旧证书直到旧证书到期。控制面仍每 15 秒复核长连接身份；旧证书过期后会断开，Agent 用新证书重连。当前 Agent 在控制流断开时关闭数据监听及活跃连接，因此每次旧证书到期会有一次连接中断。无中断交接需另行设计运行时和控制流所有权移交。磁盘权限保持 0600，私钥不经网络或日志传输。

## 失败与安全边界

- 旧证书未通过 TLS 链、数据库指纹或节点状态校验时返回统一拒绝；无证书的首次入网仍只走一次性令牌路径。
- CSR 公钥不匹配、签名错误、非 Ed25519、过大或字段未知时拒绝，不写授权。
- 响应丢失产生的未使用证书授权由过期清理回收；同一节点有效授权数量有硬上限。
- 控制面签发与数据库授权必须同一事务提交；HTTP 响应只在提交后发送。
- Agent 若证书文件更新失败继续使用旧证书并重试；一旦旧证书已过期，数据监听按现有配置租约失效机制关闭。

## 验收

在独立 PostgreSQL 16 测试库和真实 TLS 测试服务器验证：首次入网、临近到期续签、旧证书重叠、新证书重连、过早/过期/吊销拒绝、CSR 公钥不匹配、响应丢失重试、重新入网撤销旧续签授权、权限与原子落盘。正式服务器 Agent 长期运行验收仍需真实节点入网后进行。

## 后续补充：在线控制流交接

上文描述的是最初的续签实现。后续新增 [Agent 控制流证书交接设计](2026-09-27-agent-stream-certificate-handover-design.md)：正常续签成功后，Agent 在现有 WebSocket 上提交新证书，控制面在同密钥、同节点、数据库授权验证后切换该连接的周期复核证书，因此正常旧证书到期不再要求断线。异常断线和配置租约到期仍按原有失效机制关闭数据运行时。
